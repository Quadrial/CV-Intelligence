# Requirements Document

## Introduction

This feature adds a public portfolio page to the CV generator web app. Authenticated users can build a portfolio by selecting content from their existing CV profile, optionally importing a portfolio generated by an external AI tool, and publishing it at a unique shareable URL. Visitors who receive the link can view the portfolio without logging in.

## Glossary

- **Portfolio**: A curated, publicly accessible web page that showcases a user's professional profile, projects, skills, and experience.
- **Portfolio_Builder**: The in-app interface that allows authenticated users to compose and publish their portfolio.
- **Portfolio_Page**: The public-facing, read-only page rendered at a unique URL for unauthenticated visitors.
- **Portfolio_Record**: The persisted Supabase database row that stores a user's portfolio content and metadata.
- **Slug**: A URL-safe, unique string identifier used to address a Portfolio_Page (e.g., `/portfolio/jane-doe-abc123`).
- **Import_Payload**: A JSON or structured-text document produced by an external AI tool that describes a portfolio.
- **Owner**: The authenticated user who created and controls a Portfolio_Record.
- **Visitor**: Any person who accesses a Portfolio_Page via its shareable URL, without requiring authentication.
- **CV_Profile**: The existing user profile stored in Supabase containing fullName, email, phone, location, linkedinUrl, githubUrl, portfolioUrl, summary, experience, education, skills, projects, certifications, publications, awards, memberships, and references.

## Requirements

### Requirement 1: Portfolio Creation

**User Story:** As an authenticated user, I want to create a portfolio page from my existing CV profile, so that I can showcase my work publicly without re-entering my information.

#### Acceptance Criteria

1. WHEN an authenticated user navigates to the Portfolio section, THE Portfolio_Builder SHALL display a form pre-populated with data from the user's CV_Profile.
2. WHEN a user saves a portfolio for the first time, THE Portfolio_Builder SHALL generate a unique Slug and create a Portfolio_Record in the database.
3. WHEN a user saves an updated portfolio, THE Portfolio_Builder SHALL update the existing Portfolio_Record without changing the Slug.
4. THE Portfolio_Builder SHALL allow the user to select which CV_Profile sections to include: summary, experience, education, technical skills, soft skills, projects, certifications, awards, publications, and links (LinkedIn, GitHub, portfolioUrl).
5. WHEN a user attempts to save a portfolio with no fullName, THE Portfolio_Builder SHALL prevent saving and display a validation error.

---

### Requirement 2: Shareable Public URL

**User Story:** As an authenticated user, I want a unique shareable link for my portfolio, so that I can send it to recruiters or collaborators.

#### Acceptance Criteria

1. WHEN a Portfolio_Record is created, THE Portfolio_Builder SHALL derive a Slug from the user's fullName combined with a short random suffix to ensure uniqueness.
2. THE Portfolio_Builder SHALL display the full shareable URL to the Owner after the portfolio is saved.
3. WHEN an Owner clicks the copy-link button, THE Portfolio_Builder SHALL copy the shareable URL to the clipboard.
4. THE Portfolio_Builder SHALL provide a button that opens the Portfolio_Page in a new browser tab.
5. WHEN a Slug is generated, THE Portfolio_Builder SHALL ensure the Slug contains only lowercase alphanumeric characters and hyphens.

---

### Requirement 3: Public Portfolio Page Rendering

**User Story:** As a visitor, I want to view a user's portfolio at a shared URL, so that I can learn about their professional background without needing an account.

#### Acceptance Criteria

1. WHEN a Visitor navigates to `/portfolio/:slug`, THE Portfolio_Page SHALL render the portfolio content without requiring authentication.
2. WHEN a valid Slug is provided, THE Portfolio_Page SHALL display the Owner's name, summary, experience, education, skills, projects, and any other sections the Owner chose to include.
3. WHEN an invalid or non-existent Slug is provided, THE Portfolio_Page SHALL display a 404-style "Portfolio not found" message.
4. THE Portfolio_Page SHALL be responsive and render correctly on mobile, tablet, and desktop viewports.
5. WHEN a Portfolio_Record has `is_published` set to false, THE Portfolio_Page SHALL display a "This portfolio is not available" message to Visitors.

---

### Requirement 4: Portfolio Import from External AI Tool

**User Story:** As an authenticated user, I want to import a portfolio generated by an external AI tool, so that I can publish it quickly without manually re-entering content.

#### Acceptance Criteria

1. WHEN a user selects the import option, THE Portfolio_Builder SHALL accept a pasted JSON or plain-text Import_Payload.
2. WHEN a valid Import_Payload is provided, THE Portfolio_Builder SHALL parse it and populate the portfolio form fields with the extracted data.
3. WHEN an invalid or unparseable Import_Payload is provided, THE Portfolio_Builder SHALL display a descriptive error message and preserve the current form state.
4. WHEN an Import_Payload is successfully parsed, THE Portfolio_Builder SHALL allow the user to review and edit the imported content before saving.
5. THE Portfolio_Builder SHALL map Import_Payload fields to the corresponding CV_Profile fields: name, summary, experience, education, skills, projects, and links.

---

### Requirement 5: Portfolio Visibility Control

**User Story:** As an authenticated user, I want to control whether my portfolio is publicly visible, so that I can take it offline without deleting it.

#### Acceptance Criteria

1. THE Portfolio_Builder SHALL provide a publish/unpublish toggle that sets the `is_published` flag on the Portfolio_Record.
2. WHEN an Owner unpublishes a portfolio, THE Portfolio_Page SHALL immediately become inaccessible to Visitors and display a "not available" message.
3. WHEN an Owner re-publishes a portfolio, THE Portfolio_Page SHALL immediately become accessible to Visitors again.
4. THE Portfolio_Builder SHALL display the current publish status clearly to the Owner.

---

### Requirement 6: Navigation Integration

**User Story:** As an authenticated user, I want to access the portfolio builder from the main navigation, so that I can find it alongside my other tools.

#### Acceptance Criteria

1. THE AppShell SHALL include a "Portfolio" navigation link that routes to the Portfolio_Builder page.
2. WHEN a user navigates to `/portfolio-builder`, THE AppShell SHALL render the Portfolio_Builder within the authenticated layout.
3. THE Portfolio_Page at `/portfolio/:slug` SHALL render outside the authenticated AppShell layout so Visitors can access it without logging in.
